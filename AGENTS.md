## Boundaries

- The first complete release includes radio exploration, recordings, live translation, and bounded autonomous topic monitoring. A complete CLI and optional TUI share service operations. The persistent service owns jobs; client exit must not stop them. Geographic exploration and DVR belong to the initial terminal experience.
- Most expected speech and music are non-English. Preserve original scripts and per-span language evidence, including mixed and unknown states. English is the primary translation target and the only implemented target. Claim language quality and simultaneous capacity only for measured profiles.
- Local processing is the default. Paid use needs explicitly configured finite limits. Enforce exact accounting and atomic worst-case reservations before dispatch, including retries and fallback. Retain unresolved charges across crashes and billing periods. Missing bounds fail closed; overload must not trigger paid processing automatically.
- Models and retrieved content cannot grant permissions or change budgets. Models propose actions; validated service policy executes them. Treat network data, files, database records, model output, and terminal text as untrusted boundaries. Keep semantic uncertainty explicit rather than disguising it as arbitrary deterministic scoring.
- Keep capture independent of analysis and rendering, with bounded buffers, queues, resource admission, and recovery. Preserve originals while retained, provenance, revisions, timing, and gaps. Rankings describe measured source coverage, not worldwide popularity.
- Extend typed source/transform/provider contracts for audio, IQ, packets, telemetry, and text. Reuse the canonical scheduler, ledger, storage, configuration, logging, HTTP, and retry mechanisms. Do not create parallel infrastructure or assume every signal is audio. Follow the lawful-use scope; hardware starts with reception. Historical ciphers remain separate from modern supplied-key cryptography using maintained implementations.

## Ownership and seams

`sigy-core` has no dependencies. `sigy-service` owns the SQLite catalog, migrations, accounting, and library ownership. Interfaces reuse those operations. `sigy` owns command parsing and output. Domain values validate before storage or execution. Never replace exact monetary strings or integers with floating point, drop uncertain liabilities, or dispatch on an idempotent replay of a submission transition. The single library lock must outlive the catalog connection.

Use the existing [local controller](docs/decisions/0002-local-controller.md) and [capture journal](docs/decisions/0003-capture-journal.md). Recovery invalidates old workers. Control and listen streams are owned by `LocalStream`. Never drop a raw Interprocess stream after writing. Follow [local stream close](docs/decisions/0071-local-stream-close.md). Do not expose capture dispatch or completion before source authorization, resource enforcement, and verified media publication exist.

Source authority and HTTP acquisition live in `sigy-service::sources`. Immutable revisions live in `storage::sources`. Share one acquisition instance, preserve destination checks and explicit grants, and keep asynchronous DNS cancellable. A transfer receipt is not verified media. Redirects use immutable opt-in policy, at most three hops, the original deadline, and checked destinations at every hop. Follow [authorized redirects](docs/decisions/0007-authorized-redirects.md). Do not introduce implicit proxies, retries, or permission expansion.

Directory adapters live in `discovery`, with refresh and cache transactions in `storage::discovery`. Reuse the controller's worker supervisor. A refresh merges a bounded page, never implies a complete catalog, never starts playback or a listen, and cannot grant private-network authority to returned stations. Refresh, search, show, favorite, registration, playlist resolve, retained-file playback, direct listen, and `record hls` do not report a click or a vote. `radio click` is the only sender: `GET /json/url/{stationuuid}`, redirects denied, returned stream URL discarded, and `/json/vote/` never requested. Follow [directory clicks](docs/decisions/0010-directory-clicks.md) and [directory refresh](docs/decisions/0006-radio-discovery.md). Preserve exact-request replay and immutable source provenance.

Keep [favorites](docs/decisions/0008-radio-favorites.md) separate from provider observations. Cache maintenance must preserve saved identities. Optional [proxy routing](docs/design/network-routing.md) remains planned: separate proxy and target grants, explicit DNS trust, no direct fallback, and truthful peer evidence are prerequisites.

Recording files live behind `recordings`. `storage::dvr` owns exact reservations and publication with the capture journal. Preserve the 14-day and 50 GB defaults, kept and archive protection, interrupted liabilities, and delete-before-release ordering. Follow [recording and retention](docs/decisions/0005-recording-and-retention.md). The user-installed FFmpeg executable is the configured decoder. FFmpeg receives a local published file, or a pipe of bytes the service already fetched, under a protocol whitelist for that input. It does not receive a source URL. The service does not open the audio device. Follow [direct listen](docs/decisions/0011-direct-listen.md), [segment playback](docs/decisions/0027-segment-playback.md), [retained episode playback](docs/decisions/0020-retained-episode-playback.md), [ICY observations](docs/decisions/0013-icy-observations.md), [HLS media playlists](docs/decisions/0012-hls-media-playlist.md), [playlist resolution](docs/decisions/0009-playlist-resolution.md), and [decoded formats](docs/decisions/0014-decoded-formats.md). Windows retained system output uses the bounded client-owned helper in [Decision 0084](docs/decisions/0084-bounded-windows-audio-output.md). Changes to recording, playback, or HTTP acquisition require `cargo verify-media` in addition to `cargo verify`. Exported sidecars are snapshots, not permissions or the current retention authority. Internet radio and podcasts precede RF adapters. Keep RF, IQ, and packet contracts distinct from audio.

`sigy mcp` speaks MCP 2026-07-28 on stdio and is packaged at `agent-plugin/` for Agent Plugins 1.0.0. Tools run existing commands against the startup `--data-dir`. They cannot select another library, change a budget, pass a shell command, mutate a task, publish a finding or briefing, create or change a claim, or add a profile. Do not expose `sigy update` through `sigy mcp`. Follow [agent plugin](docs/decisions/0021-agent-plugin.md). MCP still requires an explicit `--data-dir`. Help, updates, and independent backup operations do not resolve a default library.

`vendor/libsqlite3-sys` is retained third-party source with a documented SQLite patch override. Preserve its notices and bytes, do not apply first-party formatting, and verify changes against [native provenance](vendor/README.md). Do not manually change checksum expectations to conceal an unexplained source change.

### Commands

`cargo verify` from the repository root is the local entry point. It runs `sigy-xtask`: vendor and script checks, the release-tag changelog heading check, formatting, warnings-denied Clippy, workspace tests, build, and `cargo audit --deny warnings`. It requires cargo-audit and fails if a check is unavailable. The commands are in `crates/sigy-xtask`. A tag push also requires a matching `## version` changelog heading. `## Unreleased` is not that heading.

`cargo verify-media` stays local. It runs the ignored native-media tests on one thread. It uses `SIGY_TEST_FFMPEG` when set, otherwise `ffmpeg` on `PATH`. It is not part of ordinary hosted verify.

`cargo verify-coverage` is the additional local coverage gate. It measures at least 80% line coverage per crate with `cargo-llvm-cov`, including ordinary and native fixtures, all workspace crates, build scripts, and test sources, with no source exclusions. It requires cargo-llvm-cov, llvm-tools, and FFmpeg, refuses a concurrent run, and keeps unique measured receipts. Raise coverage with real tests. Never exclude code to pass. Do not claim passing coverage without a successful current run.

`cargo visual-qa` renders the bounded offline gallery of 78 synthetic frames. `cargo readme-hero` regenerates the README hero pair. Neither command is part of `cargo verify`, and neither qualifies native terminal fidelity or acoustic output. Image provenance lives in [interface images](docs/development/interface-images.md) and [visual QA](docs/development/visual-qa.md).

### Prerequisites and lint

Use the pinned toolchain and preserve `Cargo.lock`. Regenerate the lock intentionally after manifest changes. `.cargo/config.toml` limits Cargo to two jobs. Ordinary tests use two threads. Workspace lint policy forbids `unsafe_code`, denies `unwrap_used` and `expect_used`, and warns on Clippy `all` and `pedantic`. Verification turns those warnings into errors. Split or redesign code that exceeds a lint. Do not allow the lint away.

### What doctor reports

`sigy doctor` is a read-only preflight. It does not refresh a cache, contact a network, or admit work. It reports the pace of completed recognition on this library, or that the pace is unmeasured. That pace is the delay that keeps a monitored recognition job live after its last seal. It also reports the wall time of queued recognition audio at that pace. A new recording still publishes while recognition is queued and after its monitor is paused. That recording stays out of the sentence until a recognition job exists, and a capture gap is not audio. Doctor also reports recognition worker cost from empty-group snapshots: the highest job-object peak committed memory and the CPU sum, or that the cost is unmeasured. The figure is not a host budget. It also compares the retained audio of admitted recognition jobs with the busy time of completed recognition, or says that comparison is unmeasured. That sentence is not a clock time for an empty queue and it is not a host budget. A stale directory row stays until an explicit `radio refresh`.

### Platform and publication

A push to `main` runs `cargo verify` on one standard GitHub-hosted Windows runner, plus Linux and macOS all-target compile and lint and the fail-closed platform fixtures named in `.github/workflows/verify.yml`. That workflow does not raise the Actions spending limit. Ubuntu and macOS do not run the full Windows suite. A Linux-only test runs in hosted verify only when the workflow names it.

`scripts/install.sh` and `scripts/install.ps1` install the `sigy` binary. They are not the verification entry point. A source-install one-liner fetches the script from GitHub and builds `main`. From a checkout, the script installs that checkout. `sigy update` installs a newer `main` commit, and `sigy update --check` only reports it. When GitHub CLI is logged in, Git uses that login.

Ordinary increments do not require a pull request or a tag. Temporary branches are permitted when useful. Integrate verified work into `main` promptly and remove obsolete branches after integration. A supported GitHub release waits until active work records a roadmap stage exit. Source-only development prereleases are allowed at meaningful verified checkpoints. Publish one only after the local gates and hosted CI pass for the exact commit. Preserve older tags. Distribute no unqualified binaries or models. `main` tracks `blisspixel/sigy`. Public source availability does not qualify product support.

Keep one coherent implementation of shared behavior. Add enforceable invariants when recurring mistakes expose a structural weakness. Scorecard is supporting supply-chain evidence, not proof of product correctness. Do not fabricate reviews, tests, support claims, or maturity to improve a score.
