# 0090: Desktop discovery and native listening

Date: 2026-10-11. Status: implemented bounded increment with local gates and actual delegated Linux contract evidence. Schema v51 and IPC v52 remain unchanged. [Active work](../development/progress.md#2026-10-11-desktop-completion) owns executed evidence. Omarchy device and remaining TUI acoustic checks are deferred by the user until after publication.

## Problem

The remaining desktop issues require a useful filtered fetch inside the explorer, audible live playback on ordinary Windows FFmpeg builds, and bounded native execution in a delegated Linux user session. Null decoding and a running service do not establish acoustic output.

## Decision

- `tui NAME` and explicit country, language, tag and health flags initialize the same validated cache filter as CLI search. `R` then `y` explicitly requests one matching directory page. Confirmation freezes the applied scope; editing and selection never grant network work. Favorites remain local choices and cannot become an upstream filter.
- A separate bounded observer keeps rendering and player controls available while the service owns the refresh. It submits one exact automatic request ID, observes for up to 15 seconds and rereads the same ordered cache scope. Closing the explorer stops observation, not an admitted refresh. Generation and catalog checks prevent old progress or pages replacing a newer search. Failures preserve cached rows and durable request identity. Empty/no-match guidance preserves filters and the custom library path.
- An effective POSIX locale may suggest a known country after setup. It is an optional printed command, not geolocation, a default filter or automatic network authority. An explicit country takes precedence; `C` and `POSIX` produce no suggestion.
- Windows direct system listening now uses the same fixed CPAL helper and checked PCM pipeline as retained output. The service remains the sole network acquirer. The client passes acquired bytes to FFmpeg over stdin, receives finite checked floating-point samples over stdout, and forwards bounded frames to the helper. FFmpeg receives no station URL or output device. Null and non-Windows output retain their existing adapters.
- Direct PCM has a 15-minute media bound, the existing acquisition byte bound, two queued chunks, a finite output-byte ceiling and a 30-second execution margin. Completion requires aligned finite samples, a successful decoder, terminal progress agreeing with counted samples, helper accounting and actual empty-group closure. Decoder progress, estimated presentation, native closure and a user's acoustic observation stay separate. Large async pipeline frames are boxed; the CLI regression also bounds the live output future.
- Linux native work uses an explicitly delegated systemd user unit on systemd 254 or later. The manager places Sigy's main process in `sigy-control`; bounded worker groups are siblings beneath the empty delegated parent. The adapter verifies exact membership, owner, canonical path, controllers and manager lifecycle properties before group creation. No process migration above the owned unit, privileged installer or uncapped fallback is introduced.
- A documented local ProcessKit 3.3.4 patch adds an explicit delegated-parent constructor. Existing pre-exec placement, kill and recursive membership code remain shared. Memory, zero swap, CPU and task caps are read back before execution. Native process admission is serialized and bounded separately from the 256-task ceiling. Each spawn leaf receives a fixed share of that ceiling before placement, preventing migration from bypassing a full parent task limit. Task-limit evidence includes those owned leaf limits. Precompiled seccompiler filters deny new processes, permit ordinary bounded threads and return `ENOSYS` for `clone3` to allow the libc thread fallback. The policy also covers the x32 process-creation numbers on x86_64. Adoption and limit replacement are unavailable for strict groups.
- Background services use a stable library-bound transient unit. Native CLI/player commands use finite transient client units, preserve argv without environment expansion, and watch their launching process. Existing stdin and requested-parent fences remain effective. `KillMode=control-group`, final SIGKILL and a five-second stop timeout let the manager clean the complete native subtree after main-process death. Metadata-only service operation remains possible without a user manager; native work refuses there.
- Linux decoding first checks a known one-second WAV in the same bounded native group, with a five-second deadline and actual drain on refusal. This rejects incompatible progress conventions without inventing media duration. A hosted FFmpeg 6.1.1 case reported 512 ms for one second; CI retains its refusal regression and builds a signed, SHA-256-pinned FFmpeg 9.0.2 fixture for exact media tests. This small clock check does not establish general runtime or codec qualification.

## Verification and limits

Verification includes independent stereo samples, hostile PCM/progress, explorer generation/confirmation failures, warnings-denied lint, full ordinary/native/coverage gates, and actual delegated Linux tests for thread/process caps, CPU throttling, memory pressure, cancellation and owner SIGKILL. Linux loopback media exercises direct null listening, recording, retained playback and restart without a public station. A separate Windows live station check was heard through this computer's headphones. Omarchy device evidence remains separate until executed.

This is resource containment for trusted, qualified local runtimes, not a hostile-code or network sandbox. Same-user cgroup mutation is not prevented. Linux memory-controller accounting differs from Windows committed-memory accounting. Windows' existing suspended-create assignment limitation remains. Empty Linux groups still publish no new cost fields. No broad device matrix, language qualification, stage exit or supported release follows from these changes.
