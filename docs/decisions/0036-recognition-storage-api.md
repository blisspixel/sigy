# Recognition storage API

Date: 2026-09-23. Status: public read-only storage API implemented; mutations remain internal test staging until native supervision is available.

The service now exposes bounded Rust reads for recognition job status and paged history. Admission, cancellation and atomic result publication are crate-private and compiled only for internal tests. This prevents an external Rust caller from creating a durable job that current production code cannot finish. The staged mutations use the existing [v26 schema](0035-transcript-revision-storage.md), single analysis worker slot and recording read lease. Schema and local IPC stay v26. No CLI, MCP or controller dispatch route is added. `analysis transcribe` still refuses work, and no recognizer is selected or run.

Staged admission binds the job ID, exact published input revision, expected transcript parent, profile ID and SHA-256. A versioned manifest hashes the catalog's recording checksum, exact timeline bytes, retained object key, byte length and media interval. The input descriptor contains no source URL or arbitrary filesystem path. The initial ceiling is one retained interval, 64 MiB and 60 seconds. The transaction rechecks current retained identity, parent and worker capacity before insertion. Exact request replay returns history without a work token, including after media expiry; changing a request under the same ID fails. Retranscription requires a new explicit ID and exact parent.

Staged completion requires both the opaque fresh-admission work token and an internal `ReapedLocalAsr` capability. Its fields are private, it cannot be deserialized, and its entire definition is test-only. Only explicitly synthetic tests can construct it in this increment. A future supervisor must establish process-tree drain before these mutations can enter production; root-process exit, library-lock acquisition, a caller boolean and model output are insufficient. Current production paths can neither admit nor complete a native job. Recovery still refuses active native rows found in a catalog and retains their leases. Bringing the staged code into production requires a separate reviewed supervisor integration.

The staged publication implementation checks exact request, generation, manifest and profile bindings, then validates at most 256 ordered, nonoverlapping cues, 4,096 UTF-8 bytes per cue and 65,536 text bytes in total. Original script bytes are preserved, and wording stays `uncertain`. Coverage must exactly match the pinned interval and source checksum. Decoded checksum syntax, bounded sample rate and sample count are checked. Integer decoded duration must agree with the pinned duration within one sample. This is a consistency check on submitted evidence, not proof of decoding, time alignment, model execution or quality; the native parser and profile still need qualification.

A valid zero-cue result publishes `no_text` with completed coverage. It does not assert silence or a language. Failed and cancelled jobs publish no transcript, coverage or decision. Cancellation holds the read lease and wins over a queued result after proven cleanup. Invalid results become failed jobs only through that same cleanup capability. A successful transaction inserts the immutable transcript revision, all cues, coverage, the zero-USD decision and terminal job state together. A storage failure rolls back every insert and retains the active lease. No paid request or ledger event is created.

Successful completion replay compares the exact stored result and writes nothing. Other terminal outcomes return retained history. Before a new result is published, the transaction rechecks current pin, source identity and parent. Input replacement refuses an active native job inside the existing supersession transaction. A directly injected newer pin makes the stale completion fail without a result. This increment does not implement active-worker replacement or waive cleanup.

Historical Rust reads return at most sixteen revisions or cues per page and at most 65,536 serialized JSON bytes, including escaped text and metadata. Cue pagination binds an exact transcript revision and preserves sparse legacy ordinals. Legacy placeholders and new `no_text` outcomes remain distinct. Historical results stay readable after media deletion. Future CLI rendering must sanitize terminal text while retaining these original bytes; these APIs do not render text.

Tests use catalog fixtures without reading media or launching native processes. They cover exact replay and changed-request refusal, shared admission limits, Unicode and escaped-byte pagination, sparse legacy cues, append-only parent history, zero-cue coverage, cancellation and restart leases, stale identity, input replacement, malformed output and rollback at every publication stage. Three compile-fail examples verify that external admission and external construction or deserialization of the cleanup capability are unavailable. These checks do not complete [operation 23](../development/language-pipeline.md).
