## Open gates and known limitations

- **Network isolation:** native recognizers are not network-sandboxed by the operating system. Static import checks only. Gate for recognition on user recordings before release.
- **Process containment:** Job Object limits on Windows. On Linux the containment library enforces cgroup limits only at the real cgroup root, so under a systemd session or service, or in a container, native recognition and translation fail closed with `limits-unavailable`; confirmed in a Debian container with and without a private writable cgroup. A delegated-cgroup path (service in one leaf, each worker in a sibling leaf) is required before Linux can run them. macOS fails closed. Suspended-spawn assignment window remains. After a restart, only Windows requeues native jobs; Linux and macOS interrupt them.
- **Recognition scope:** one job publishes one transcript. Each process hears at most 30 seconds, at most 1,024 windows, with the 64 MiB byte cap unchanged. A phrase at a window edge while audio remains waits, and the next window starts at that phrase. A phrase with no earlier break is stored through the window end. Model hashing takes seconds per run. Each window still runs with `language=auto`.
- **Quality:** no language is qualified. The 32-clip calibration has limited reference diversity, and the 126-control judge profile failed. A calibrated independent evaluator, broader published references and the unopened holdout remain necessary.
- **Durability:** physical power loss, complete media backup and restore on another host, and the 5000 ms segment window as a measured guarantee are unproven.
- **Platforms:** the Linux container run found and fixed a Unix-only Clippy error and an init that left an existing directory at 0755, which made the service refuse to start. Unix parent-death and peer checks, installers and OS startup are unqualified; macOS has not run.
- **Public stations:** the [live station pilot](../../research/experiments/local-asr/live-station-pilot.md) has recorded and transcribed all eight public stations (Spanish, two Arabic, Portuguese, Swahili, Canadian French, Chinese, Hindi). A stream-edge header delay that blocked the Canadian French station is fixed, and that station has since been recorded and transcribed.
- **Live HLS:** [live HLS](../decisions/0042-live-hls.md) recording and master-variant resolution pass loopback fixtures and recorded the three HLS-only pilot stations (Chinese, Hindi, Arabic) after two compatibility fixes; a capture still ends at its first gap.
- **Chunking:** [chunked recognition](../decisions/0049-chunked-recognition.md) transcribes a retained recording longer than 60 seconds as one job. Each process hears at most 30 seconds. A phrase that reaches the window edge while audio remains waits, and the next window starts at that phrase. A phrase with no earlier break is stored through the window end, so a word there can still be cut. 208 worst-case coverage rows fit one 65,536-byte page and 209 do not. A 15-minute capture is about 30 windows and fits. Output seeking can miss the 60-second decoder deadline on a late slice of a long file. One recording holds the single recognition slot until its windows finish. The earlier pilot measurement remains: a 60-second request published 63 to 74 seconds of audio.
- **Coverage:** `cargo verify-coverage` enforces at least 80% line coverage separately for every workspace crate. It uses `cargo-llvm-cov` 0.9.0 and the pinned toolchain's `llvm-tools`, includes test sources and build scripts without source exclusions, and runs ordinary and native fixtures. It refuses concurrent profile ownership and preserves unique JSON receipts. The full measurement passes all five crates; counts are recorded in the snapshot above. This remains an additional local gate because it runs native media fixtures; ordinary CI still runs `cargo verify`.
- **Next implementation:** extend the verified publication delegation and stable effect identities to task-owned collection and processing, then reconcile the finite [task workflow](../design/task-workflows.md#first-acceptance-slice) through existing service operations and the durable job pool. Interrupted and uninterrupted effects must agree, and cancellation must affect only owned future work. Qualified local planning follows that execution contract. Finish operation 36's terminal measurement and operation 37's bounded sample contracts alongside host-capacity and language qualification. Operations 23, 24 and 25 still need measured quality. Recognition arrival and empty-group cost snapshots do not establish a host budget. Owned capture now reuses civil schedules with explicit user ownership and separate capture caps; end-to-end topic and missed-event quality remain open. The [delegated-cgroup audit](../../research/experiments/native-boundary/delegated-cgroups.md) records the Linux containment and parent-death work needed before native workers run on ordinary Linux hosts. Real Linux evidence and the Windows suspended-spawn assignment window remain open.
- **Paid processing:** dispatch is unavailable; the product's default paid budget is zero. When enabled, paid use draws down a one-time lifetime allowance that never refills.

**Native spawn hang (2026-09-25, open).** In one full `cargo verify-media` run, the recognition fixture's stand-in recognizer stayed in its initial suspended state for more than 14 minutes (one thread, wait reason `Suspended`, 0 CPU, 2 MB working set), so the job stayed `running` and the test hit its deadline. The stand-in then survived its service's exit, which means it was never assigned to the Job Object that would have killed it. The fixture passed alone three times and the full suite passed on the next run. The suspected window is inside the containment library's create-suspended, assign and resume sequence. ProcessKit 3.3.4 returns the child only after create-suspended, assign, and resume. Its reaper is armed after that process call returns, so it runs on unwind between creation and assignment, and it does not run while the call is still blocked. Abrupt service death does not run `Drop`. A Sigy-side timer cannot name or kill a child the library has not returned. The window stays open. Creation-time job assignment is the containment the pinned safe wrappers do not expose, and this repository forbids `unsafe_code`.
