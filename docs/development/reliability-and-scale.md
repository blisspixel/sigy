## Engineering standard

Build complete useful workflows in bounded increments. A small initial workload must exercise production authority, storage, acquisition, supervision and publication paths. Synthetic fixtures isolate faults; representative recordings, real platform lifecycle checks and sustained workloads establish operational usefulness. Every claimed profile needs both kinds of evidence.

Accept core engineering and experience quality together. Captures, immutable evidence, permission, accounting, cancellation and recovery need explicit invariants and fault proof within each declared profile. The interface should also feel ambitious and enjoyable: fluid exploration, generous instrument space, expressive real activity, discoverable interaction and rewarding investigation. Each UI brief includes both compact access and a composed expansive view. Evaluate continuity of source/query/playhead context, repeated setup and navigation friction as part of that journey. Modern terminal capability tiers can add richer interaction after their compatibility and resource bounds are measured. Curiosity, receiver personalities, historical ciphers and creative explanation remain meaningful product scope under the shared [intent](../../INTENT.md).

Keep one service authority for accepted intent, resource admission, canonical jobs, exact accounting and publication. Capture, processing, diagnostics and rendering have independent failure and capacity boundaries. All external execution returns bounded data for validation; it cannot mutate policy or publish directly. Models and retrieved material remain proposals and observations.

Scale is a workload and deployment qualification, not a source-count promise. Preserve stable identities and bounded contracts from a laptop to additional workers. Define migration and ownership before introducing multiple writers, remote execution or source shards. Preserve the useful local installation throughout.

## Acceptance journeys

Use these complete user tasks to decide whether a package is useful. A passing internal API alone does not complete a journey. CLI and TUI must agree on the same service state and evidence, including partial outcomes. Set concrete input fixtures, expected artifacts, resource ceilings and measured acceptance criteria in the implementation brief before running the journey.

| Journey | Expected experience | Important difficult case |
| --- | --- | --- |
| Discover a place | Type or select a country/territory or major city from the worldwide reference, combine filters, inspect cached scope/age, compare stations, then explicitly listen or record | Native-script aliases, ambiguous place, an uncached country, missing place/station coordinates and offline operation; no cached match never means no station exists |
| Use a radio DVR | Explicitly listen and capture, rewind retained segments, inspect aligned cues, protect a passage and return to the latest playable position while other sources record | Segment/codec transitions, gaps, expiry/save races, open tail, decoder failure, two clients and independently delayed analysis |
| Understand a passage | Read the original beside a selected qualified target, inspect uncertainty and reach the retained interval | Code switching, wrong-target output, an unqualified direction, a clipped boundary word and expired audio |
| Follow a finite topic | Accept two sources and finite bounds once; inspect progress after client exit; receive exact owned evidence and a coverage-aware outcome | Quoted instructions, one failed source, no literal match, shared processing, restart and cancellation |
| Check and correct a finding | Follow exact revisions to the original, hear available evidence, correct a cue and inspect affected results | Retention during inspection, conflicting correction, stale translation and a report whose original has expired |
| Recover normal operation | Diagnose a held stage, preserve the last useful state and resume only work whose authority remains current | Sleep, regressed clock, mirror failure, unavailable model, full disk and a second fault during recovery |

Unfamiliar signals, physical receivers and expressive interpretation extend these same inspection principles when their later adapters exist. They do not become extra mandatory first-release implementations because their architecture is represented here.

## Package boundaries and integration

Before each package, record the concrete behavior, current source/test owners, schema/IPC impact, compatibility policy, failure/partial states, maximum work and next reviewable artifact. Reuse an existing service operation whenever it supplies the required authority. A new command or view names an actual user action; proposed CLI syntax is not published as working help. Record consequential alternatives in the relevant decision, rather than copying research into every design.

Keep one primary runtime integration at a time on this host. Independent research, rendered design and isolated bounded experiments can continue, but resource timing needs a recorded quiet/contended profile. Short-lived branches integrate after their exact changes pass the applicable gates; unverified optional work stays isolated without accumulating unrelated changes. Scope failures to their affected behavior and maintain the existing lint/test policies.

Before each increment, write a short acceptance brief in its decision or active work record: one user outcome; frozen inputs and starting state; permitted operations and finite bounds; expected CLI/TUI artifacts; the important failure, recovery and partial states; and the exact evidence needed. State what remains outside that increment. A country-reference slice resolves the declared offline identities and reuses current filters; it need not also migrate ordering, probe streams or build continuous playback. Preserve visual craft at compact and wide sizes in every interface slice. Mixed-load capacity qualification remains S-06 work, not a new prerequisite for every filter change.

Use discover, explicitly listen/record, inspect retained material, read original/qualified translation and cite a result as the delivery spine. Advance the packages needed by each step without claiming that an unfinished journey already works. Default human views explain source/scope, result or hold, uncertainty and next permitted action; detailed inspection preserves exact revisions and authority, and structured output retains stable identities. Partial outcomes state what completed, what remains usable and what requires another explicit action.

Keep absence states precise: not observed within the declared coverage; observed but undecoded; decoded with unqualified meaning; and historical evidence whose media has expired. These statements cannot substitute for one another or imply worldwide absence. A beautiful map, a successful decode or a completed workflow is useful only within the scope its evidence actually supports.

## Exact publication contract

In one consistent catalog transaction, freeze the task scope and collection/processing grant digests, exact occurrence and recording identities, ordered receipts, canonical jobs, transcript and translation revisions, explicit translation targets, uncovered/unprocessed intervals, missing outcomes and bounded citations. Bind a versioned publication intent to this manifest's digest before effects. This is narrower than the existing broader monitor checkpoint, which remains readable with its historical meaning.

Reuse canonical finding validation and the existing publication executor. Each effect and immutable receipt commit together. A current retention check can refuse a fresh citation without rewriting the frozen manifest or earlier finding. Cancellation and scope drift fence later effects. Partial collection or processing produces explicit partial coverage; literal matches and valid references do not establish semantic support.

Bound scanned rows, snapshot bytes, allocations, execution time and citations separately. Page or stream evidence instead of collecting all selected cue rows before applying the citation cap. Keep catalog work inside a consistent bounded snapshot; no network, native execution or user interaction occurs in its transaction. Exhaustion records truncation and a partial outcome. A replay must reproduce the admitted manifest and effects rather than reading newer evidence.

Choose explicitly whether publication waits for remaining authorized processing or freezes a requested partial result now. Record that choice and observation cutoff in the admitted run. One logical run cannot mix earlier and later coverage as its effects advance. Fresh observations use a new versioned snapshot; replay of the original request returns its original result. The historical broad-monitor checkpoint path keeps its existing meaning.

## Shared work and cancellation

Keep admission interests immutable. Append task-owned withdrawal receipts identifying the exact interest and cancellation generation. In the same immediate transaction, fence future task admission, withdraw the selected interests and determine remaining effective authority. Other task, monitor or direct interests preserve the job. Legacy interest reconstruction remains conservative; absent historic direct provenance is not proof that no direct authority existed.

An unshared queued job can be cancelled without launch. An unshared running job enters cancelling through the existing supervisor. Cancellation completion and capacity release require actual completion and empty-group evidence. A stale worker cannot publish after its generation is fenced. Preserve read leases while native reads can still run. Do not resurrect a cancelling canonical job when a new owner attaches; hold or refuse the attachment. Future recomputation requires explicit new attempt authority and exact accounting.

Current direct interests do not distinguish independently cancellable callers. This increment must not imply that they do. Monitor pause keeps its existing treatment of admitted work. Collection cancellation, processing cancellation and publication cancellation retain distinct documented effects.

Preserve historical admission-only processing cancellation and exact replay; new withdrawals require explicit versioned intent. Successful immutable-result reuse is separate from resurrecting cancelling/failed work. Current unique task-owned occurrences prevent two tasks from sharing one canonical recording/job. Production acceptance covers task-plus-direct/monitor sharing and two independent task jobs; two-task same-job sharing is future-model conformance only. Bound remaining-owner lookup across historical interests and hold/roll back when it cannot establish authority safely. Follow the [S-03 briefs](near-term-implementation.md#s-03a-explicit-owner-withdrawal).

## Translation for people and agents

English is the default and an initial evaluation direction. A translation target is a service-validated, immutable processing parameter, independent of interface locale, source metadata, user hint and observed language spans. Use bounded standards-based tags for known languages and preserve meaningful script and regional distinctions. Freeze canonicalization rules used in durable identity; registry changes cannot rewrite past digests.

Include target identity in canonical translation jobs, task/monitor grants, translation revisions, target-specific latest selection, citation provenance, search and report exports. Sharing requires the same exact original revision, target, profile and transformation parameters, within compatible authority and data-destination policy. Different targets must coexist. A newer result in another target cannot silently stale or replace an earlier target's result. Multiple requested targets consume separately admitted work and bounded fan-out.

The current schema constrains translations to `en`, uses an `english` cue field and omits target from job identity. The change needs a deliberate schema/IPC migration, not merely a prompt option. Preserve existing IDs, English revision order and historical task grants. Proposed flags are documented only after parser implementation. An unsupported direction preserves originals and reports a reason; another language, dialect, script or paid route requires explicit compatible authority.

Qualify directed source-variety/target-variety/profile/task pairs. Evaluate original-text translation and ASR-output translation independently, then downstream retrieval and report usefulness. English references and backtranslation are supplementary evidence, not qualification for another target. Canadian French, Navajo and Klingon remain required substantive cases. Unknown or hypothetical languages and symbol systems retain typed representation identities, candidate hypotheses and supplied legends; they do not receive an invented registered language tag or a universal-understanding claim.

## Resource and capacity contract

Separate lifetime authority from reusable execution capacity. Collection seconds/bytes, processing allowance and paid liability never refill through failure or policy revision. CPU, memory, scratch space, worker slots and device slots become reusable only when their owner is proven finished. Persist enough claim and generation state for restart reconciliation; uncertainty holds capacity or marks the executor unavailable rather than assuming a disappeared PID proves safety.

Define aggregate host admission across all worker kinds, with explicit capture/control/storage headroom. Start optional GPU execution with one admitted execution per physical device; increase concurrency only after complete-pipeline measurements. Device memory estimates are observations, not enforceable VRAM quotas. Keep Linux cgroup memory and Windows committed-memory measurements labeled by mechanism.

Measure queue counts, retained audio duration, oldest eligible age, model-specific service time, reserved media and pin pressure. Measure catalog commit/scan latency, WAL/checkpoint growth, decoder overhead, model loads, worker output buffers, cleanup and thermal degradation. A library-wide mean recognition pace is useful but cannot qualify a heterogeneous host envelope. Pressure feedback can defer work with bounded hysteresis; it cannot change authority or silently open paid fallback.

Preserve source rotation and the oldest-batch share. Examine expensive-job starvation before selecting cost-aware scheduling. Keep live latency, batch progress and retention urgency explicit. Overload yields named held/degraded states and uncovered or unprocessed time. Rendering may drop frames; acknowledged durable work and audio cannot be silently discarded.

## Growth to larger deployments

The [storage and memory contract](../design/storage-and-memory.md) separates local transactional authority, bounded spool/scratch, retained bulk objects and rebuildable retrieval/context views. Pi-class hosts, gaming machines, 2 TB/20 TB NAS media and reproducible infrastructure deployments are confirmed target scenarios, not supported profiles. Media capacity, catalog size, ingestion rate, query demand and inference throughput are independent measurements. [Storage research](../../research/36-storage-placement-and-capacity.md) and [memory research](../../research/37-knowledge-formats-and-temporal-memory.md) record the primary evidence and limitations.

Carry these contracts across each deployment: immutable content/profile/target identities, bounded operation envelopes, attempt-generation fencing, publication validation, explicit destinations and exact reservations. Keep durability truth in canonical storage; notifications, metrics, caches and search projections remain rebuildable. Extract a backend or protocol seam when the next measured package needs it, then require conformance and migration evidence. Creating unused abstraction layers is not itself a scale result.

| Deployment | Boundary to preserve | Trigger and additional proof |
| --- | --- | --- |
| Personal machine or one server | One catalog owner, local durable media, bounded supervised workers | Measured CPU baseline, supported filesystem and service lifecycle, resource envelope and restore |
| Additional execution host | Authority stays at the service; worker receives exact hashes, a fenced lease and scoped transfer capabilities | A measured execution bottleneck, authenticated revocable destination grant, worker loss/partition/reconnect and duplicate result evidence |
| Multiple coordinators or storage hosts | One transactional authority per declared partition; global paid liability has one authoritative reservation path | Measured catalog/storage bottleneck, backend conformance, migration, split-brain prevention, restore and cross-partition admission design |
| Source shards and large deployments | Exclusive fenced capture ownership and explicit placement/rebalance history | Proven clock/gap behavior, failed-owner takeover, partition recovery, bounded object lifecycle and independently reproducible reports |

SQLite remains the local default and is not placed on shared network storage. Adding an execution worker alone does not require a database replacement. PostgreSQL is a researched candidate when concurrent writers or measured storage requirements justify it. A broker may notify; durable catalog intent remains recoverable without notification delivery. Remote publication fencing prevents stale effects but does not prove remote execution stopped or liability ended. A partitioned worker cannot automatically be replaced until duplication, containment and retained-liability policy permits it.

Warm workers, batching, indexes and memoization are experiments, not automatic upgrades. Resident workers need a separate per-request isolation/completion contract compatible with today's empty-group publication requirement, bounded cache lifetime, cancellation and contamination checks. Caches include target, context and profile identity and respect privacy boundaries. Speech gating must measure missed speech, songs, code switches and boundary words; it cannot declare a skipped interval understood.

## Measurement, analysis and artistic interaction

Record an explicit measurement model: original format, channel/sample coordinates, clock epochs, transform versions, units and known uncertainty. Audio decoding/downmix/resampling creates a derivative with a reproducible source mapping. Missing samples, retained silence, skipped material and unrecognized speech remain distinct. Relative digital amplitude cannot become an RF-power or acoustic-pressure claim. Later RF/telemetry profiles preserve device configuration, sample-clock evidence, calibration basis and gap semantics; actual hardware qualification remains required.

Distinguish observed material, what a source alleges, analytical interpretation and a candidate hypothesis. Keep contrary references, assumptions and next discriminating observations. Track quoted, syndicated and rebroadcast relationships only with evidence and an explicit unresolved state. Outlet counts do not establish independent corroboration. A frozen sampling frame explains selection, excluded sources and missingness. No literal match is not proof of event absence, and directory coordinates cannot establish speaker, subject or transmitter location.

Make exploration expressive through actual geography, time, original scripts and replayable material. Wide layouts can show originals beside the chosen target; compact layouts retain the same identities and return path. Optional focused listening, poetic explanation and later sonification are separate representations with declared provenance and mappings. They cannot rewrite transcripts or pretend to be received audio. Preserve literal operational failures and stable machine output. Humor is optional, sensitive to context and separately evaluated per locale. Meaningful motion, text equivalents, reduced motion and calm empty/error states belong to the existing terminal contract.

## Planner admission and useful results

Begin with one supported finite method over accepted sources and available profiles. Version the runtime/model, method, prompt, tool schemas and capability snapshot. A natural-language planner must actually interpret the requested task and select valid typed steps; a keyword shortcut or accepted JSON schema cannot establish that capability. Ask once about consequential unresolved scope, then advance within the accepted grant without repeated permission requests.

Bound planning calls, context/input/output bytes, tokens, wall time, proposal count, retries and effects independently. Persist concise proposals, validation and stop reasons before effects, not hidden reasoning. Repeated proposals without new evidence reach a named no-progress outcome. Missing capability, unqualified quality, exhausted limits and conflicting evidence produce useful partial or unsupported results. They cannot silently expand destinations, choose a different translation target or open a paid route.

## Operational scorecard

Replay equivalence applies where retained inputs and accepted scope are identical. For actual live outages, verify admitted effects and charges remain exact and explain differences through recorded gaps, missed occurrences or unavailable input. A second fault during recovery must leave a truthful recoverable or refused state. Never reconstruct broadcasts that were not observed merely to match a fixture's uninterrupted outcome.

Before each workload run, freeze the commit, OS/filesystem/service mode, host/device/driver identities, profile hashes, language pairs, source count and bitrates, duration, retention, limits and fault schedule. Predeclare acceptance thresholds and collection overhead after a baseline, before held-out runs. Report distributions and worst cases, not just averages.

| Property | Observe and retain |
| --- | --- |
| Capture integrity | Planned versus recorded time, explicit gap causes, segment/hash/media continuity and acknowledged effects |
| Responsiveness and fairness | Control p50/p95/p99, oldest eligible wait, service-pass delay, live lag and batch progress |
| Sustainable resources | CPU/thermal behavior, labeled native memory, device pressure, scratch/media/WAL/catalog growth and cleanup duration |
| Recovery | Durable effects/charges before and after restart, second fault during recovery, migration rollback, verified clean restore and recovery time |
| Language usefulness | Per directed pair fidelity, severe errors, observed-language accuracy, usable coverage, missing outcomes, retrieval and citation support |
| Private operation | Bounded diagnostic bytes/labels, dropped-event counts, payload/secret canaries, no automatic uploads and healthy capture under diagnostic failure |
| Understanding | Finding-to-original replay, alternative hypotheses, correction impact, coverage explanation and clear unsupported outcomes |

Use bounded local counters/histograms first. Avoid job, topic, source URL or transcript values as metric labels; put necessary correlation IDs in finite private event records. No telemetry collector is required. Durable task/evidence state supports recovery even when diagnostics are unavailable.

Readiness includes actual platform and sustained-workload evidence, not just line coverage or synthetic success. Keep process termination separate from physical power-loss evidence. Keep benchmark language quality separate from human-reviewed localization and unrestricted fluency. Preserve research limitations and unsuccessful runs so the next increment starts from evidence.
